ApexCharts print test (#3352)

Widen this window first (the bug needs a chart wider than the print width, 700px by default), then press Cmd+P.

Every chart on this page shares one setting, so the print is a clean before/after. Currently:

switch mode  |  loads ../../dist/apexcharts.js, so run npm run build first if you changed the source.

Do not mix the two modes on one page. A chart that keeps its screen width makes the whole document wider than the sheet, and the browser then scales everything down to fit, including the charts that were sized correctly. That is why a mixed page makes the fix look like it shrinks charts: it is the browser's document scaling, not the chart's layout.

Printing cannot be covered by the automated suites (a headless PDF is the only programmatic print, and it cannot be snapshot-compared), so this page is the manual check.

1. Dashboard card (clips its overflow) — the reported case

Default: all twelve months, inside the card. With ?off: cut off around Aug at the card's edge, which is the bug as reported.

2. Narrow card (46% wide)

Default: complete, scaled down to the card by the print stylesheet, since 700px does not fit a 46% column. With ?off: cut off far earlier.

3. Full-bleed chart (nothing clips it)

Default: laid out at 700px, so the document no longer overflows the sheet and the labels stay at their normal size. With ?off: the chart stays at its screen width, so the browser either cuts it off or scales the whole document down to fit, depending on the browser and its scale setting. Complete-but-tiny is the same bug wearing a different hat.
